Question one
: how many is each member borrowing


Query:
q1 = run("""
   SELECT member_id, first_name, last_name, COUNT(checkout_id) AS num_checkouts
   FROM members
   LEFT JOIN checkouts USING (member_id)
   GROUP BY member_id
   ORDER BY num_checkouts DESC
""")
print(q1)


reason ??
I used the members table because I needed every member, even the members who didn't borrow anything.
 I used a left join to include all members because if I used a normal join it would drop the people with no checkouts.
I used count(checkout_id) instead of count(*) because count(*) would count rows and say 1 instead of 0 for the people with no checkouts

Webpage vs database:
Webpage vs. Database as data sources
API stands for Application Programming Interface. You send a request, and it sends back exactly what you asked for, organized, tidy, and ready to use right away. (return ready to use data- rarely changes- easier-uninvited)
web scraping : we go to the page itself, the same page ordinary people see with their own eyes, read the code behind it, and pull out what we need. Exactly like walking into the kitchen ourselves.(return the whole page- changes a lot and make break your code- more work- invited)


Why this mattered for my project: the database part was easy because sql already gave me exactly the columns I asked for with clear names like member_id and checkout_date The kickoff page didn't come like that since it's made for a person to read, not a program. I had to find the table in the html myself and the column names were "Member ID" with a space and a capital letter instead of member_id, so I had to rename everything by hand before I could even combine it with the rest of my data ( one real example from my project in task 2 I found 5 checkouts from the kickoff page where the member_id 1104 1150 1201 didn't match anyone in the members table at all this never happened with any of the 391 checkouts that came from the database because a real database only lets you save a member_id that actually exists the kickoff page has no rule like that since its just a webpage someone typed up by hand so a wrong or made up id could get saved with no warning thats a real example of why the comparison mattered it actually caused one of the four problems i had to fix later)
